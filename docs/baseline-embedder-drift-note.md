# Data contract note: baseline embedder vs engine dense embedder (PARITY reconcile item)

The quality-gate baseline (`user_data/baselines/uiux-baseline.json`) records the embedder actually measured in the M4 spike (`data/eval/runs/20260905-075117-raw-vs-enriched-spike.json`, variant A = enriched dense): `gemini-embedding-001` at 3072 dims. The engine's corpus config currently declares a different dense embedder default (`gemini-embedding-2` at 768 dims). Because an eval run is only comparable to the baseline when the four-corner tuple (schema_version, index_version, eval_set_version, embedder_version) matches exactly, the gate ABORTS on this mismatch by design — it never compares metrics across tuples. To produce a comparable gate run, the PARITY wave must reconcile the engine's dense embedder to the measured 001/3072 (or re-measure the baseline under 2/768); until then the drift abort is the correct, intended behavior.
